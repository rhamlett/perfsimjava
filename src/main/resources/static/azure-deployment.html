Performance Problem Simulator - Java 21

🚀 Deploy to Azure

Deploy to Azure App Service with GitHub Actions and OIDC authentication

Overview

This deployment uses OpenID Connect (OIDC) for secure, passwordless authentication between GitHub Actions and Azure. No secrets or credentials are stored in your repository.

Step 1: Clone the Repository

Fork or clone the repository to your own GitHub account:

  1. Go to github.com/rhamlett/perfsimjava
  2. Click Fork to create your own copy
  3. Clone your forked repository locally (optional, for local development)

Step 2: Create Azure Resources

In the Azure Portal, create the following resources:

2a. Create a Resource Group

  • Navigate to Resource Groups in the Azure Portal
  • Click Create
  • Name: rg-perfsimjava (or your preferred name)
  • Region: Choose your preferred region

2b. Create an App Service Plan

  • Navigate to App Service Plans
  • Click Create
  • Select your resource group
  • Name: asp-perfsimjava
  • Operating System: Linux
  • Pricing Tier: B2 or higher recommended

2c. Create an App Service (Web App)

  • Navigate to App Services
  • Click Create
  • Select your resource group and App Service Plan
  • Name: perfsimjava (must be globally unique)
  • Runtime stack: Java 21
  • Java web server stack: Java SE (Embedded Web Server)

Step 3: Configure Microsoft Entra ID

Create an App Registration for GitHub Actions to authenticate with Azure:

3a. Create the App Registration

  1. Navigate to Microsoft Entra ID → App registrations
  2. Click New registration
  3. Name: github-actions-perfsimjava
  4. Supported account types: Accounts in this organizational directory only
  5. Click Register

3b. Note the Application Details

From the App Registration overview, copy these values (you'll need them for GitHub):

  • Application (client) ID
  • Directory (tenant) ID

Also get your Subscription ID from the Subscriptions page in Azure Portal.

Step 4: Configure Federated Credentials

Set up OIDC trust between GitHub and your App Registration:

  1. In your App Registration, go to Certificates & secrets
  2. Select the Federated credentials tab
  3. Click Add credential
  4. Select GitHub Actions deploying Azure resources
  5. Configure the credential:
    • Organization: your-github-username
    • Repository: perfsimjava
    • Entity type: Branch
    • GitHub branch name: main
    • Name: github-actions-main
  6. Click Add

Step 5: Assign Azure Permissions

Grant the App Registration permission to deploy to your App Service:

  1. Navigate to your Resource Group (rg-perfsimjava)
  2. Go to Access control (IAM)
  3. Click Add → Add role assignment
  4. Role: Contributor
  5. Members: Select your App Registration (github-actions-perfsimjava)
  6. Click Review + assign

Step 6: Configure GitHub Secrets

Add the Azure credentials to your GitHub repository:

  1. Go to your forked repository on GitHub
  2. Navigate to Settings → Secrets and variables → Actions
  3. Add these repository secrets:
    • AZURE_CLIENT_ID – Application (client) ID from Step 3b
    • AZURE_TENANT_ID – Directory (tenant) ID from Step 3b
    • AZURE_SUBSCRIPTION_ID – Your Azure Subscription ID

Step 7: Deploy

The included GitHub Actions workflow will automatically deploy when you push to the main branch:

  1. Make any change to your repository (or just trigger the workflow manually)
  2. Go to Actions tab in GitHub to monitor the deployment
  3. Once complete, access your app at https://your-app-name.azurewebsites.net

Post-Deployment

After deployment, consider enabling these features in the Azure Portal:

  • WebSockets – Required for real-time dashboard updates (Settings → Configuration → General settings)
  • Application Insights – For monitoring and diagnostics
  • Health check – Set path to /health for container health monitoring

Important

This application is designed for testing and diagnostics training. Do not deploy to production environments where simulated failures could impact real users.
