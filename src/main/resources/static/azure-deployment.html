Azure App Service Deployment Guide

This guide covers deploying the Performance Problem Simulator to Azure App Service using the Java 21 Blessed Image.

Prerequisites

  • Azure CLI installed and configured
  • Java 21 JDK installed locally
  • Maven 3.9+ installed
  • An Azure subscription

Method 1: Deploy via Azure CLI

Step 1: Build the Application

# Clean and package the application
mvn clean package -DskipTests

# Verify the JAR was created
ls target/*.jar

Step 2: Create Azure Resources

# Set variables
RESOURCE_GROUP="rg-perfsimjava"
APP_NAME="perfsimjava"
LOCATION="eastus"
APP_SERVICE_PLAN="asp-perfsimjava"

# Create resource group
az group create --name $RESOURCE_GROUP --location $LOCATION

# Create App Service Plan (Linux)
az appservice plan create \
    --name $APP_SERVICE_PLAN \
    --resource-group $RESOURCE_GROUP \
    --sku B2 \
    --is-linux

# Create Web App with Java 21
az webapp create \
    --name $APP_NAME \
    --resource-group $RESOURCE_GROUP \
    --plan $APP_SERVICE_PLAN \
    --runtime "JAVA:21-java21"

Step 3: Deploy the JAR

# Deploy using ZIP deploy
az webapp deploy \
    --resource-group $RESOURCE_GROUP \
    --name $APP_NAME \
    --src-path target/perfsimjava-1.0.0.jar \
    --type jar

Step 4: Configure App Settings

# Set application configuration
az webapp config appsettings set \
    --resource-group $RESOURCE_GROUP \
    --name $APP_NAME \
    --settings \
    WEBSITE_WEBDEPLOY_USE_SCM=true \
    JAVA_OPTS="-Xms256m -Xmx512m -XX:+UseG1GC"

Method 2: Deploy via Maven Plugin

Step 1: Add Azure Maven Plugin to pom.xml

<plugin>
    <groupId>com.microsoft.azure</groupId>
    <artifactId>azure-webapp-maven-plugin</artifactId>
    <version>2.12.0</version>
    <configuration>
        <resourceGroup>rg-perfsimjava</resourceGroup>
        <appName>perfsimjava</appName>
        <region>eastus</region>
        <pricingTier>B2</pricingTier>
        <runtime>
            <os>Linux</os>
            <javaVersion>Java 21</javaVersion>
            <webContainer>Java SE</webContainer>
        </runtime>
        <deployment>
            <resources>
                <resource>
                    <directory>${project.basedir}/target</directory>
                    <includes>
                        <include>*.jar</include>
                    </includes>
                </resource>
            </resources>
        </deployment>
    </configuration>
</plugin>

Step 2: Deploy

# Build and deploy in one command
mvn clean package azure-webapp:deploy -DskipTests

Method 3: Deploy via GitHub Actions

Create Workflow File

Create .github/workflows/azure-deploy.yml:

name: Deploy to Azure App Service

on:
  push:
    branches:
      - main

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    
    steps:
    - uses: actions/checkout@v4
    
    - name: Set up Java 21
      uses: actions/setup-java@v4
      with:
        distribution: 'microsoft'
        java-version: '21'
        cache: 'maven'
    
    - name: Build with Maven
      run: mvn clean package -DskipTests
    
    - name: Deploy to Azure
      uses: azure/webapps-deploy@v2
      with:
        app-name: 'perfsimjava'
        publish-profile: ${{ secrets.AZURE_WEBAPP_PUBLISH_PROFILE }}
        package: 'target/*.jar'

Post-Deployment Configuration

Enable Application Insights

# Create Application Insights resource
az monitor app-insights component create \
    --app $APP_NAME-insights \
    --location $LOCATION \
    --resource-group $RESOURCE_GROUP

# Get the instrumentation key
INSTRUMENTATION_KEY=$(az monitor app-insights component show \
    --app $APP_NAME-insights \
    --resource-group $RESOURCE_GROUP \
    --query instrumentationKey -o tsv)

# Add to app settings
az webapp config appsettings set \
    --resource-group $RESOURCE_GROUP \
    --name $APP_NAME \
    --settings \
    APPLICATIONINSIGHTS_CONNECTION_STRING="InstrumentationKey=$INSTRUMENTATION_KEY"

Configure Health Probes

az webapp config set \
    --resource-group $RESOURCE_GROUP \
    --name $APP_NAME \
    --health-check-path /health

Enable WebSockets

az webapp config set \
    --resource-group $RESOURCE_GROUP \
    --name $APP_NAME \
    --web-sockets-enabled true

Recommended JVM Settings

az webapp config appsettings set \
    --resource-group $RESOURCE_GROUP \
    --name $APP_NAME \
    --settings JAVA_OPTS="\
-Xms256m \
-Xmx512m \
-XX:+UseG1GC \
-XX:+HeapDumpOnOutOfMemoryError \
-XX:HeapDumpPath=/home/LogFiles/heapdump.hprof \
-Xlog:gc*:file=/home/LogFiles/gc.log:time,level,tags"

Scaling Options

Scale Up (Vertical)

# Upgrade to Premium tier for better performance
az appservice plan update \
    --name $APP_SERVICE_PLAN \
    --resource-group $RESOURCE_GROUP \
    --sku P1V3

Scale Out (Horizontal)

# Add more instances
az webapp scale \
    --name $APP_NAME \
    --resource-group $RESOURCE_GROUP \
    --instance-count 3

# Browse to app

    --name $APP_NAME \
    --resource-group $RESOURCE_GROUP

Troubleshooting

Common Issues

Application Not Starting

Check that the JAR file is executable and the main class is correctly specified in the manifest. View logs with az webapp log tail to see startup errors.

WebSocket Connection Failed

Ensure WebSockets are enabled on the App Service. Also verify that ARR Affinity is enabled if using multiple instances.

Out of Memory Errors

Increase the heap size in JAVA_OPTS or scale up to a larger SKU. The B2 SKU provides 3.5 GB RAM which should be sufficient for testing.

Production Warning

This application is designed for testing and diagnostics training. Do not deploy to production environments where simulated failures could impact real users.

Cleanup

# Delete all resources
az group delete --name $RESOURCE_GROUP --yes --no-wait
