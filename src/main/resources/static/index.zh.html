🔥 CPU 压力 i️

会生成运行密集加密操作的工线程，以对 CPU 核心施加压力。

📊 记忆压力 i️

分配填充随机数据的缓冲区块。多重分配堆叠——模拟渐进式内存泄漏。

🧵 线池饥饿 ⚠️

块 servlet 线程以模拟线程池耗尽。服务器对新请求变得无响应。

⏱️ 时长说明： 每个阻塞请求运行时间为指定时长。如果线程>池大小（~200），超余请求会排队并分波运行。总时≈ duration × ⌈threads/200⌉.

🔌 连接池 i️

模拟JDBC连接池耗尽。并发查询超过池容量，导致超时——这是常见的Java生产问题。

🔍 线程转储会显示线程在Semaphore上等待——这和HikariCP/C3P0池耗尽完全相同。

❌ 未完成的请求 i️

通过触发100%错误概率的请求，生成 HTTP 500个错误。错误出现在 AppLens 和 Application Insights。

📊 每个请求在失败前都会完成可见工作，并显示在请求延迟监视器中。

💥 应用崩溃 ⚠️

终止JVM进程。 Azure 自动重启——在事件日志中观察恢复情况。
